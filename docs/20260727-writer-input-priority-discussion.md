# Writer 输入优先级与结构保真 — 设计提案

> **状态：W1–W4 已实现并入 1.3.1**  
> 日期：2026-07-27  
> 前提版本：**1.3.0**  
> 发布版本：**1.3.1**  
> 触发：V8 成稿丢掉大纲内表格框架；D 中长度要求被突破；用户纠正「A 非辅助」  
> 相关：`writing_constraints.py`、`writer.py`、`structure_guard.py`、`outline_parser.py`

本文是对「各输入权重如何设定」的**修正提案**，取代此前分析里「A=辅助、表=半硬」的表述。实现前以本文为准。

---

## 1. 用户拍板（相对先前分析的修正）

| 点 | 先前说法 | 修正后 |
|----|----------|--------|
| **页数** | 未建模导致突破 | 可视为「坏提示词 / 弱信号」；**不作为本轮硬目标**（仍可进 checklist 原文，但不做页数硬校验） |
| **大纲结构 + 已有表格** | 半硬 Seed，易被改成段落 | **不可接受被改掉** → 结构保真为硬规则；表内中文草稿须**英文化**，不得 verbatim 保留 |
| **A（Assessment / 评分）** | 「辅助」 | **否**。要求与评分是命根子 → 与 D 同级硬约束源 |
| **B（背景）** | 软参考 | **同意**保持软 |
| **D 点名必须套用某文档** | 未单独建模 | **必须能做到**（见 §3.4） |

---

## 2. 目标优先级（实现时的真源顺序）

从硬到软：

```text
P0  结构保真（锁定大纲 heading 树 + key_points 内已有表/列表框架）
P0  引用完整性（ALLOWED SOURCES / citation_guard）——已有，不变
P1  A 作业要求与评分标准（assessment 定稿）
P1  D 具体要求（字数区间、必含/禁止、以及「必须套用文档 X」）
P2  大纲 Seed 中的事实性要点（case 名、提案名等）——已有方向，加强验收
P3  已落库 section_directives / confirmed_facts
P4  B 背景笔记（软参考，可截断）
P5  页数表述（弱信号；本轮不硬校验）
```

原则：

- **不得为了凑字数 / 写流畅而牺牲 P0–P1。**
- 冲突时：用户本轮精修 instruction 可显式覆盖局部；`run-agent` 整篇重生不得擅自改大纲结构或删表。

---

## 3. 规格要点

### 3.1 大纲结构保真（硬）— 含表格

**禁止**：改 heading 层级/顺序、合并/拆节、把 `key_points` 里已有的 Markdown 表（或解析出的表框架）改成纯散文而丢列。

**要求**：

1. Writer 系统提示写死：若本节 `key_points` 含表格行（`|` 分隔或明确「Table / 表」框架），输出中**必须保留同构 Markdown 表**（列对齐；可填内容，不可删列/改框架除非要点写明可改）。
2. **语言**：成稿全文（含表头与单元格）默认 **academic English**。大纲表里的中文草稿仅作内容提示，须翻译/改写为英文，**禁止 verbatim 保留中文单元格**（除非 HARD CONSTRAINTS 明确要求中文）。
3. 成稿校验：`verify_draft_against_constraints`（或独立 `structure_guard`）按节检查：
   - 大纲 leaf/节标题是否都出现；
   - 该节 Seed 若含表 → 正文是否含 ≥1 个 Markdown 表且列数大致匹配。
4. 不通过则进入 repair（专项：「恢复表格框架」），而不仅是字数补写。

解析侧：继续依赖 `outline_parser` 把 Word 表写入 `key_points`；校验以锁定后的 `paper_outline` 为准。

### 3.2 A 升为硬约束源（与 D 并列）

**现状问题**：抽取以 D 为主、A 作 excerpt；校验几乎不碰评分条目。

**提案**：

1. `extract_writing_constraints`：**A 与 D 同等送入**；checklist / must_include 明确要求覆盖评分维度、必交结构、作业硬性条款（仍「不编造原文没有的约束」）。
2. `to_prompt_block`：A 不再只是短 excerpt，而是 **Assessment HARD 块**（可截断但提高上限，或分「评分标准 / 硬性要求」两段）。
3. 校验：对 A 抽取出的 `must_include` / checklist 关键词做与 D 同级的缺失检测；缺则 repair。

文案上对外：**A = 得分规则与作业契约；D = 本次写作执行细则**；二者都是硬，不是「D 硬 A 软」。

### 3.3 字数（保持硬目标，修正非对称）

- 继续以 **words** 为主（页数见 §1）。
- 修正「只扩不压」：
  - 节偏短 → 扩写（现有）；
  - 节/全文明显超 `word_max` → **压缩一轮**（或分节重写时下调 budget）；
  - 容差可收紧（例如超标报警阈值从 `hi*1.25` 降到 `hi*1.1`），具体实现时再定。

### 3.4 D 中「必须套用某文档」（硬）

当 D（或 A）出现类似：

- 「必须遵循 / 套用 / 按 … 模板 / 使用附录 X / follow document Y」

系统应：

1. **抽取**为结构化项，例如 `must_apply_documents: [{name, role_hint}]`（`role_hint` 可映射 BACKGROUND / 某 source title）。
2. **解析绑定**：在 `project_source_documents` 中按 title / role 匹配；匹配到则把该文档 `summary_text`（或截断 `raw_text`）以 **MUST APPLY（authoritative）** 块注入 Writer，而不是当普通 B 背景。
3. **匹配失败**：`run-agent` 返回明确警告或 400（产品二选一；建议 **警告 + 仍生成**，changelog 标红；严格模式可后置）。
4. 校验：至少检查成稿是否出现该文档要求的关键标识（标题关键词 / 必含小节）；完整语义对齐仍靠模型，但「没注入文档」不可再发生。

B 默认仍软；**仅当被 D/A 点名套用** 时升格为硬附件。

### 3.5 页数（本轮明确降级）

- 不解析 pages→words，不做页数硬校验。
- 可在 UI/文档提示：长度请用 **词数** 写在 D；页数仅供人工参考。

## 4. 与现有模块关系

| 模块 | 变化 |
|------|------|
| `writing_constraints.py` | A/D 同等抽取；must_apply；字数容差与超长 issue |
| `writer.py` | 表保真系统提示；超长压缩；MUST APPLY 注入；repair 分类型 |
| 新：`structure_guard`（可选） | 节标题 + 表框架验收 |
| `outline_parser` / 锁定大纲 | 基本不变；表进 key_points 已有 |
| 精修 polish | 同源：改节时不得抹掉该节 Seed 表（除非用户指令明确） |
| citation_guard | 不变 |

## 6. 非目标（本提案不做）

- 出版级自动排版算页数  
- 用 OCR 从 PDF 图里还原表  
- 把 B 全部升为硬约束  
- 用精改替代用户重锁大纲结构

## 7. 开放项

1. 「必须套用」匹配失败：警告继续 vs 400 阻断（建议警告）。  
2. 表「同构」判定：列数相等即可，还是表头文本也要近似匹配。  
3. A 全文过长时截断策略：优先保留含 mark / criterion / must / 不得 的段落。
